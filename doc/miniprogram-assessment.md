# Mirror Tarot 上微信小程序可行性评估

> 结论先行：**技术上能跑通，产品上会被规则改掉。** 抽牌 + 正逆位 + 解读的核心链路，在微信小程序的审核口径里等同于「算命/抽签」，属平台未允许内容。真正的障碍不是开发量，是三条硬约束同时压上来。

---

## 一、三条硬约束

### 1. 类目红线（决定性问题）

《微信小程序平台常见拒绝情形》第 3.2.4 条明确：

> 小程序的页面内容中，不能存在测试类内容；示例：算命，抽签，星座运势等。

实际审核口径（微信开放社区多例驳回记录）：

> 小程序涉及算卜算运势、算命、付费取名等内容，属于平台未允许内容，请移除相关内容或功能后再重新提交代码审核。

对本项目意味着什么：

| 现有元素 | 审核视角 |
|---|---|
| 78 张塔罗牌 + 洗牌抽牌 | 「抽签」 |
| 正位 / 逆位 | 「占卜」 |
| AI 解读 + 追问 | 「算命」 |
| 牌阵（关系/职业） | 「付费算命」 |

关键点：**3.2.4 是内容性质判定，不是敏感词表。** 改文案、换谐音、藏入口，在 2026 年的「机审特征库 + 人审走流程」双重机制下通过率接近于零，且多次违规会降低账号信用分。审核员只要实际走一遍「提问 → 抽牌 → 看解读」的流程就能判定。

### 2. 主体与备案门槛（时间成本）

- AI 问答类目需要申请「深度合成 - AI 问答」，**仅企业主体可申请**（个人主体不行）。
- 申请需提供**算法备案证明**。生成式 AI 面向境内公众输出内容，按现行口径需完成「大模型备案/登记 + 算法备案」，官方公开周期 3–6 个月。
- 个人主体小程序仅开放小额虚拟支付且有月度额度上限，不适合商业化。
- 成本参照：个体工商户约 ¥300–800/年即可获得企业主体资质；若使用腾讯云 CloudBase，算法备案证明可在云开发控制台 AI 板块生成，能省掉自建备案流程。
- 审核必查三件套：界面「由 AI 生成」标注、用户协议中的 AI 免责条款、输入内容安全过滤（可用 `msgSecCheck`）。

### 3. 数据架构（工程量最大的一块）

| 问题 | 影响 |
|---|---|
| 小程序 request 域名必须已备案且 HTTPS | `*.supabase.co` 无法备案 → 必须自有域名反代，或迁国内云 |
| 小程序不支持 cookie | Supabase Auth 的 session 需改为 header 传 JWT，客户端改造 |
| 邮箱魔法链接登录在小程序内体验极差 | 需改用 `wx.login` → openid/unionid（这反而是体验升级） |
| `wx.request` 不支持 SSE | 现有流式解读需改 `enableChunked` + `onChunkReceived` 手动解析分块 |
| 不能用 web-view 绕过（个人主体禁用；企业主体也只能加载已备案业务域名） | 无法直接套现有 Next.js 页面 |

## 二、支付：原来的最大顾虑已经不成立

2026-02-27 微信《小程序虚拟支付业务管理规范更新公告》要点：

- iOS 端虚拟支付**已全面开放**，与安卓、Windows、鸿蒙统一。
- 2026-04-01 起**全终端强制接入**官方虚拟支付接口，逾期判定违规。
- iOS 端享受 **15% 优惠费率**，2026 年微信不额外收取技术服务费。
- 严禁引导用户至 APP、公众号、H5、个人号或外部网站完成支付。

抽成对比：

| 渠道 | 抽成 | 备注 |
|---|---|---|
| 小程序 iOS 虚拟支付 | 15% | 2026 限时费率 |
| 小程序安卓 | 0.6% | 微信支付 |
| App Store 小企业计划 | 15% | 需申请，年营收 <100 万美元 |
| Stripe（海外 H5） | 2.9% + $0.30 | 无平台审核 |

**结论：抽成不是障碍，类和备案才是。**

## 三、三条路径对比

### 路径 A：小程序 + 彻底去占卜化

改法：塔罗 → 「意象卡 / 情绪投射卡」；取消正逆位；取消预测叙事；牌名替换为情绪词（迷雾 / 锚点 / 回声）；类目选「工具 - 效率」。

代价：**这不是迁移，是换一个产品。** Mirror Tarot 的气质有相当一部分寄生在塔罗符号系统上——去掉它，剩下的是一个普通的情绪日记 App，在红海里没有差异化。

评分：可行但不建议。

### 路径 B：微信内 H5（公众号 / 朋友圈）

- 无需小程序类目审核，现有 Next.js 代码几乎零改动。
- 但分享能力弱、无小程序入口留存、支付要走 H5 支付（需商户号 + 域名备案）。
- 公众号推「塔罗」内容同样会被限流或删文。

评分：适合小规模私域，撑不起增长。

### 路径 C：出海（英文 H5 / App）

- App Store 的 Tarot / Astrology 是成熟付费类目，AI tarot journal 已有 $4.99–6.99/周 的付费先例。
- 无小程序类目审核、无生成式 AI 备案、Supabase 直连可用、支付走 Stripe / RevenueCat。
- 英文用户对「journal / reflection」的付费意愿，显著高于中文用户对「算命」的付费意愿（后者心理预期是免费）。
- 改造成本主要在数据层：78 张牌的牌义需要英文版（`src/lib/tarot/cards.ts` 目前只有 `zhName`），架构不用动。

评分：**如果目标是变现，期望值最高。**

## 四、如果仍要做小程序：最小验证方案

不要先开发。用 3 天做一个「去塔罗化」的价值测试：

1. 把 `/reading/daily` 的牌面换成抽象意象图（去掉牌名、去掉正逆位），保留 AI 解读。
2. 找 20 个种子用户用两周，只看一个指标：**没有「塔罗」两个字之后，他们还觉得这东西有价值吗？**
3. 如果价值感立刻消失 —— 说明产品价值寄生在占卜叙事上，小程序这条路从根上不通，别再投入。

这个测试成本 3 天，能省掉 3 个月的开发和备案。

## 五、合规清单（无论走哪条路，国内都需补齐）

1. **显式标识**：《人工智能生成合成内容标识办法》（2025-09-01 施行）要求 AI 生成内容在文本起始/末尾或界面显著位置标注。当前解读正文无标注，需补「本内容由 AI 生成」。
2. **导出也要带标识**：第四条第（六）款——提供下载、复制、导出功能时，须确保文件含显式标识。`SharePoster` 导出图片属于此列，**必须加标**。
3. **隐式标识**：导出图片的元数据需含生成属性、服务者名称、内容编号。
4. **用户协议**需明确说明标识方法与样式（第八条）。
5. **隐私政策 + 注销入口**：`/account` 当前缺失（此前审查已记录），且涉及出生信息，属高风险项。
6. 若主打「陪伴感」，需关注《人格化 AI 交互服务管理暂行办法》（2026-07-15 施行）。
7. 不得向未成年人提供诱导性内容；严禁「化解 / 转运 / 消灾」话术。

---

## 六、建议

优先级：**出海 > 微信内 H5 私域 > 小程序**

理由：同一个产品，在小程序里要改产品、办备案、等 3–6 个月，且随时可能因内容违规被单方下架——整个生意建立在一个可被随时终止的许可上。而出海只需要翻译牌义 + 接 Stripe，平台风险最低、天花板最高。

小程序留到「已经有品牌和私域」之后再谈。那时候它是一个渠道，不是一个产品。
